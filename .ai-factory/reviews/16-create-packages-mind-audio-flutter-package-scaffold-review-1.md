## Findings

### 1. Stale template stub leaks `Calculator` into the public API — minor, but worth fixing now
**File:** `packages/mind_audio/lib/mind_audio.dart`, `packages/mind_audio/test/mind_audio_test.dart`

The generated `lib/mind_audio.dart` exports a `Calculator` class with an `addOne` method, and the generated test asserts behavior on it. Once any other package or app code does `import 'package:mind_audio/mind_audio.dart';`, `Calculator` is part of the consumed public surface of this package. That is misleading dead surface in a package that is meant to host audio code.

The plan explicitly said "Do not add any source files beyond what the template produces", which the implementation followed literally, but the *intent* of the milestone — "package compiling empty" — is not met: the package compiles with a non-empty, off-topic public symbol and a passing on-topic-irrelevant test.

**Suggested fix:** empty out `lib/mind_audio.dart` (leave a comment-only file or just `// Audio package placeholder. Implementations land in later milestones.`), and either delete `test/mind_audio_test.dart` or replace it with an empty `void main() {}` so it still compiles. This is low-risk; it does not change the package's pub-resolution behavior or the lockfile.

### 2. SDK constraint tightening: package requires `sdk: ^3.11.0`, root only requires `^3.9.2`
**File:** `packages/mind_audio/pubspec.yaml` line 7, vs root `pubspec.yaml` line 22

The new package declares `environment: sdk: ^3.11.0`, while the root project still declares `sdk: ^3.9.2` and the existing sibling packages (`mind_ui`, `breath_module`) declare `>=3.7.0 <4.0.0`. Because pub resolves against the intersection of all `environment.sdk` constraints, adding this package effectively raises the project's minimum required Dart SDK from 3.9.2 to 3.11.0 for everyone.

`pubspec.lock` regenerated cleanly on the developer's machine (their Dart is ≥3.11), but this is an undocumented, silent floor-raise. A contributor or CI runner on Dart 3.9.x or 3.10.x will fail `flutter pub get` with an SDK constraint error.

**Suggested fix:** normalize the new package's `environment:` block to match the siblings, i.e.
```yaml
environment:
  sdk: '>=3.7.0 <4.0.0'
  flutter: '>=3.0.0'
```
The plan permitted leaving the generated SDK constraints alone, but doing so caused a real cross-package compatibility shift. Worth correcting.

### 3. Missing `publish_to: none`
**File:** `packages/mind_audio/pubspec.yaml`

Sibling packages (`breath_module`, presumably others) set `publish_to: none` to guard against accidental publication. The new package omits it. Not a runtime bug (path-dep packages aren't published from the root anyway), but a defense-in-depth/consistency gap. Add `publish_to: none` near the top of the file.

### 4. `description`, `homepage`, `LICENSE` left as placeholders
**Files:** `packages/mind_audio/pubspec.yaml`, `packages/mind_audio/LICENSE`, `packages/mind_audio/README.md`, `packages/mind_audio/CHANGELOG.md`

- `description: "A new Flutter package project."` — boilerplate copy.
- `homepage:` — empty key (valid YAML, but a typo trap; either remove or set).
- `LICENSE` contains literal `TODO: Add your license here.` — every other internal package omits LICENSE entirely. Either delete this file or set it to match the repo's licensing posture.
- `README.md` and `CHANGELOG.md` are all-TODO template content; sibling packages don't carry these. Consider deleting both to match repo conventions.

None of these break compilation; all are noise that ages poorly.

### 5. Justification text in the plan is incorrect (documentation-only)
**File:** `.ai-factory/plans/16-create-packages-mind-audio-flutter-package-scaffold.md` Task 2

Plan says the `flutter: sdk: flutter` entry is "needed for `rootBundle`". This is misleading — no code uses `rootBundle` yet, and the entry is required simply because `flutter create --template=package` produces a Flutter package. Harmless, but worth correcting if the plan is revised.

## Runtime risk assessment

- **Nothing imports `package:mind_audio/...` yet** — confirmed implicitly: the package was just created and no other source file in the diff references it. So the stale `Calculator` symbol is dormant, not actively wired into the app.
- **`flutter pub get` already succeeded** on the implementer's machine (lockfile updated cleanly). The SDK-constraint risk in Finding #2 is environment-dependent and will only surface on contributors with older Dart SDKs.
- **No security implications**: no credentials, no native platform code, no network or storage surface introduced.

## Recommendation

Address Findings #1 and #2 before merging — they are both quick edits and prevent (1) misleading public API surface and (2) silent SDK-floor changes for other contributors. Findings #3 and #4 are convention hygiene and can ride along in the same fix. Finding #5 is plan-doc-only.
