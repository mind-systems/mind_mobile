## Critical Issues

### 1. vm.mmd line 58: `BreathViewModel` is not a valid node ID — creates orphan node

**File:** `docs/breath/session/diagram/vm.mmd:58`

```mermaid
BreathViewModel -->|"vm.stream (direct)"| StateChannel
```

In this diagram, the BreathViewModel subgraph is declared as:
```mermaid
subgraph VM["🎯 BreathViewModel (StateNotifier)"]
```

The subgraph ID is `VM`, not `BreathViewModel`. Using `BreathViewModel` as an edge source creates an implicit orphan node labeled "BreathViewModel" outside the VM subgraph, disconnected from the actual ViewModel box. The rendered diagram will show a stray box.

**Fix:** Change the source to the subgraph ID:
```mermaid
VM -->|"vm.stream (direct)"| StateChannel
```

Note: this works correctly in `module.mmd` because `BreathViewModel` IS an explicitly declared node there (line 38).

### 3. module.mmd: `BreathModuleStateChannel` placed inside `AnimationLayer` subgraph

**File:** `docs/breath/session/diagram/module.mmd:59`

`BreathModuleStateChannel` is declared inside the `AnimationLayer` subgraph alongside `BreathAnimationCoordinator` and `OrbAnimationCoordinator`. The old `LiveSessionCoordinator` was placed here because it was created by `BreathSessionScreen.initState()` alongside the animation coordinators. `BreathModuleStateChannel` is created in `BreathModule.buildSession()` at the provider factory level — architecturally it's at the module assembly layer, not the animation layer.

This is cosmetic and doesn't affect correctness, but the node description ("Создаётся в BreathModule.buildSession()") contradicts its placement in the animation subgraph.
