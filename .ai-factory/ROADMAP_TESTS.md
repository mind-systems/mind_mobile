# Mind Mobile — Test Roadmap

> Cover key business-logic nodes: state machines, domain coordinators, and invariant-heavy data flows.

## Milestones

- [x] **BreathModuleStateChannel — lifecycle transitions** — no test file exists for `lib/BreathModule/Core/BreathModuleStateChannel.dart`. Create `test/BreathModule/breath_module_state_channel_test.dart`. Write two hand-rolled fakes inline: `_FakeChannel` implements the call surface of `ModuleStateChannel` — records calls to `start()`, `unpause()`, `pause()`, `end()`, `stop()` in lists, and owns a `StreamController<ModuleState>` exposed as `.stateController`; `_FakeInstructionStream` records `sendSample(sessionId, phase, durationMs)` calls in a list. Write a `_make()` factory that instantiates both fakes plus `StreamController<BreathSessionState>` for `stateStream`, constructs `BreathModuleStateChannel`, and returns all handles. Write a `_state({required BreathSessionStatus status, BreathPhase phase = BreathPhase.inhale, int exerciseIndex = 0, SessionLoadState loadState = SessionLoadState.ready, int currentIntervalMs = 4000})` helper. Test groups: (1) **start** — first transition from pause/null to breath calls `channel.start(ActivityType.breath, sessionId)` exactly once; subsequent pause→breath calls `unpause()` instead; pause→rest also calls `unpause()`; (2) **pause** — breath→pause calls `channel.pause()` exactly once; rest→pause also calls `channel.pause()`; duplicate same-status emissions do not call again; (3) **end** — any status→complete calls `channel.end()` once; second complete emission does not call again (`_ended` guard); (4) **loadState filter** — emitting a state with `loadState != ready` triggers no lifecycle call and does not update `_previousStatus`. - [x] **BreathModuleStateChannel — instruction dispatch and flush** — extend `test/BreathModule/breath_module_state_channel_test.dart` (created in previous milestone) with three more test groups. (1) **instruction dispatch** — phase change while `status=breath` and `moduleSessionId` available calls `_instructionStream.sendSample(moduleSessionId, phase.name, currentIntervalMs)`; exerciseIndex change with same phase also triggers send; no change in either field does not trigger send; `status=pause` suppresses send; `_started=false` suppresses send; `_ended=true` suppresses send. To make `moduleSessionId` available: emit a `ModuleState(moduleSessionId: "sid")` on `_FakeChannel.stateController`. (2) **pending flush** — phase change while `moduleSessionId=null` stores state in `_pendingInstruction` and does not call `sendSample`; subsequent `ModuleState` emission with a non-null `moduleSessionId` flushes it and calls `sendSample` exactly once; a second flush with the same id does nothing (buffer cleared); if `moduleSessionId` arrives before any phase change, no `sendSample` is called. (3) **reset and dispose** — `reset()` zeroes all private fields (`_started`, `_ended`, `_moduleSessionId`, `_previousStatus`, `_previousPhase`, `_previousExerciseIndex`, `_pendingInstruction`) but subscriptions remain alive (emitting a state after reset triggers lifecycle again); `dispose()` calls `channel.stop()` when `_started && !_ended`, does not call `channel.stop()` if never started, does not call `channel.stop()` if already ended, and cancels both `_stateSub` and `_channelSub`.
