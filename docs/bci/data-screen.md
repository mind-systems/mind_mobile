# Экран данных BCI

Экран в реальном времени отображает три потока биометрики с подключённого устройства: NFB EEG-полосы, эмоциональные классификаторы и кардиоданные. Экран доступен из Home-grid без привязки к активной сессии и работает независимо от `BreathModuleStateChannel`.

## Шапка

Батарея и точки качества каналов расположены вместе слева: `[battery row] [SizedBox(8)] [Container(pill, height:22, cardColor)]` — точки внутри пилла. Правая часть шапки свободна (`Spacer`). Точки — 8×8 px с отступом 4 px; цвет по уровню сигнала: зелёный — норма, жёлтый — пограничный, красный — плохой контакт.

## Метрические бары

Каждая метрика — горизонтальная ячейка:

```
Row(
  Text(label, bodyMedium),
  Spacer,
  Text(value, bodySmall),    // целое число 0–100, или "--" если null
)
SizedBox(height: 4)
AnimatedContainer(
  height: 24,
  width: value * maxWidth,   // через LayoutBuilder
  borderRadius: 12,
  duration: 400ms, curve: easeOut,
)
```

Ячейки одной группы выстроены вертикальным `Column` с отступом 12 px между ячейками. Тело экрана обёрнуто в `SingleChildScrollView`.

## Нормализация по скользящему максимуму

SDK обещает диапазон 0..1 для NFB и эмоций, но на практике превышает его. Бары при зажатом значении 1.0 теряют динамический диапазон.

`BciDataViewModel` ведёт десять независимых скользящих максимумов — по одному на каждую метрику:

```
_maxX = max(_maxX, rawValue)
normalizedValue = rawValue / _maxX
```

Начальный пол — `1.0`: пока SDK соблюдает контракт, нормализация нейтральна. При превышении 1.0 максимум поднимается, и все последующие значения становятся пропорциональными. Бар дополнительно зажат в 0..1 как safety net.

Максимумы не переносятся между открытиями экрана — каждый VM-инстанс начинает с нуля. Каждая метрика нормализуется по своему максимуму независимо.

## Пустое состояние

Когда `!state.isConnected` — центрированное пустое состояние с иконкой Bluetooth, текстом «Устройство не подключено» и кнопкой «Подключить», ведущей на экран сопряжения. Шапка отображается в приглушённом варианте.

## Поток данных

```
NeiryBciProvider
  ├─ NfbClassifier    → Stream<BciNfbData>
  ├─ CardioClassifier → Stream<CardioData>
  └─ EmotionsClassifier → Stream<BciEmotionsData>
        ↓
BciNotifier (BciNfbUpdated / BciCardioUpdated / BciEmotionsUpdated)
        ↓
BciDataService → BciDataStateUpdated (сырые значения без нормализации)
        ↓
BciDataViewModel → нормализует → BciDataState
        ↓
BciDataScreen
```

`BiometricStreamClient` принимает те же сырые значения параллельно и шлёт их на сервер без нормализации.

## Контракт с доменом

Экран не подписывается напрямую на `BciNotifier`. Всё идёт через `IBciDataService` → `BciDataViewModel` — стандартная модульная граница, описанная в [docs/core/module-system.md](../core/module-system.md).
