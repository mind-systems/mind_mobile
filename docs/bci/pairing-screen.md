# Экран сопряжения

Экран сопряжения проводит пользователя через три последовательных этапа в одном прокручиваемом полотне: обнаружение устройства, проверка качества контактов, калибровка. Все три секции отрендерены всегда — недоступные пока показаны приглушёнными, чтобы пользователь видел путь целиком.

## Поток этапов

```
discovery ──▶ impedance ──▶ calibrating ──▶ ready
```

- **Discovery.** Список найденных устройств обновляется по мере сканирования. Если в эфире нашлось устройство из реестра известных — автоматически инициируется подключение и пользователь сразу видит индикатор «подключаемся». Когда сканирование остановилось и устройство не найдено (`!state.isScanning && state.stage == discovery`), в заголовке секции появляется кнопка повторного сканирования.
- **Impedance.** После BLE-коннекта секция оживает: на каждом канале отображается цветной индикатор качества (зелёный — норма, жёлтый — пограничный, красный — нужно поправить электроды) и числовое значение импеданса в омах под названием канала. Значение отсутствует до появления данных от устройства. Кнопка калибровки доступна; пользователь решает сам, когда сигнал достаточно чист.
- **Calibrating.** Запущенная калибровка показывает прогресс по этапам (4 точки) и инструкцию «закройте глаза». Каждую секунду воспроизводится тик-звук (`tick_clock.ogg`) — аудиальный ориентир для пользователя, сидящего с закрытыми глазами. По завершению тик замолкает, проигрывается звук-маркер, и экран переходит в финальное состояние с зелёным «ready». Сбой возвращает в impedance — повторить можно без переподключения.

## Шапка экрана

Слева — индикатор батареи. Рядом с батареей — иконка Bluetooth: синяя, когда устройство подключено (`state.stage != discovery`), приглушённая в режиме обнаружения. Справа — кнопка «Отключить». Батарея и disconnect показаны приглушёнными, пока устройство не подключено. Disconnect защищён диалогом подтверждения. Выход с экрана — свайп-бэком (iOS) или системной кнопкой назад (Android); явной кнопки закрытия нет.

## Отказ Bluetooth

Когда домен сообщает о постоянном отказе в разрешениях, экран показывает диалог с объяснением, зачем нужен Bluetooth, и кнопкой «Открыть настройки». Открытие настроек — ответственность UI, не домена. После возврата из настроек пользователь инициирует повторное сканирование кнопкой в заголовке секции Discovery.

## Контракт с доменом

Экран не подписывается на устройство напрямую. Вся коммуникация идёт через сервис-интерфейс на границе модуля: сервис конвертирует доменные события в DTO, ViewModel принимает только DTO. Это позволяет UI-пакету `packages/bci_module/` оставаться полностью отделённым от `lib/Bci/` и от вендорского SDK.

`BciChannelQualityDTO` несёт `channelName`, `quality` (`good`/`fair`/`poor`) и `impedanceOhm` (nullable — до первого измерения отсутствует).
