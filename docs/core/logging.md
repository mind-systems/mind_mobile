# Логирование

Все логи в приложении проходят через единый фасад `logPrint`. Это тонкая обёртка: вызовы кода не знают, куда в итоге уйдёт сообщение — в консоль, в Loki или в оба места одновременно.

## Назначение маршрута

Куда уходит лог, определяется переменной окружения `LOG_DESTINATION`, которая читается один раз при старте:

- `console` — только отладочный вывод (по умолчанию в release-сборках)
- `grafana` — только Loki
- `both` — оба направления (по умолчанию в debug-режиме)

В локальной разработке переменную удобно задавать через `--dart-define`. В prod-сборках `LOG_DESTINATION` не выставляется, поэтому в release без явного указания логи идут только в консоль.

## Транспорт в Loki

Когда маршрут включает `grafana`, приложение инициализирует SDK `observe` (пакет `observe-dart`). SDK отправляет сообщения в Loki по протоколу OTLP/HTTP. Каждый лог тегируется двумя метками: `project=mind` и `service=mind_mobile`. Эндпоинт OTLP настраивается через `Environment.otlpEndpoint` — в CI и prod он пуст, поэтому отправки не происходит даже при `LOG_DESTINATION=grafana`.

Инициализация SDK — первое, что происходит в `App.initialize()`, чтобы ни один лог до неё не пропал. Флаш в Loki выполняется автоматически при уходе приложения в фон и при отсоединении (`onPause` / `onDetach`).

## Фасад

`logPrint` — единственная точка входа для всех логов. Он принимает произвольный объект и форматирует его в строку. В консоль добавляется временна́я метка `[HH:mm:ss]`; в Loki уходит чистое сообщение без метки (Loki ведёт свою временну́ю шкалу).

Фасад живёт в отдельном пакете `packages/mind_logger`, который можно импортировать из любого модульного пакета напрямую. В основном коде приложения `lib/Logger.dart` реэкспортирует `mind_logger`, чтобы все 111 вызовов `logPrint` продолжали работать без изменений.

## Трассировка gRPC-вызовов

Каждый исходящий gRPC-вызов получает уникальный `trace_id`. Идентификатор инжектируется в заголовок `traceparent` (стандарт W3C) и одновременно наследуется через Dart-зону в существующий `[gRPC] … ERROR` лог на стороне телефона. В результате провальный вызов оставляет одинаковый `trace_id` и в логах телефона, и в логах сервера — их можно мгновенно свести запросом `observe-logs trace <id>`.

## Правило

Весь код — и в `lib/`, и в модульных пакетах — должен писать логи только через `logPrint`. Прямые вызовы `print`, `debugPrint` или `dart:developer log` обходят маршрутизацию и никогда не попадают в Loki.
