## Phase 57 — Pluggable tick cadence sources: RR primary + HR-derived fallback

The breath "heart" tick path couples smoothing (`SmoothedRrSource`), staleness (`HeartRateTickService`'s 10 s `_coastGraceWindow`) and the metronome into one place, and feeds only RR. In `neiry_kit` RR is computed by us on raw PPG while HR (BPM) is computed by the SDK on a separate tract — so RR can fail (observed: 45 s of solid `isArtifact=true` + a mislabeled `430 ms` "2× fast" spike) while HR keeps streaming. Goal: each cadence source fully encapsulates its own smoothing + "usable now?" status; a selector keeps all warm and auto-picks the highest-priority usable one, so a future HR-only sensor rides the same code. `ActiveRrSource` is explicitly out of scope (no liveness "fix").

## Phase 58 —  Breath lifecycle state machine — extract status/lifecycle from the tick FSM (TDD, Option A)

The breath module has a mature **tick** FSM (`BreathSessionStateMachine` progression) but no real **lifecycle** FSM. `BreathSessionStatus {pause,breath,rest,complete}` (`BreathSessionState.dart:5`) is a Cartesian smear of (lifecycle × phase-kind): `pause` means BOTH "not started" AND "manually paused" — discriminated only by the out-of-band `_hasStarted` (`BreathSessionStateMachine.dart:83`) — and breath/rest is encoded twice (in `status` and in `phase`). "Is the activity live" is reconstructed **three times** — `_hasStarted` (SM), `_started/_ended` (`BreathModuleStateChannel`), `ModuleState{idle,active}` (server) — so keep-alive has no clean local/offline signal. Plan: derive a clean local `isLive`, migrate consumers onto it (fixing the offline keep-alive gap), then surgically extract an owned lifecycle FSM — all under a characterization golden master at the **activity boundary**, with the **output schema** (`BreathSessionState` fields) as the versioned contract. The server adapter (`BreathModuleStateChannel`) is **not** re-architected — it stays server-gated and merely stops parsing `status` meanings, receiving an explicit `stop|pause|play`. Phases unnumbered (fluid). Supersedes Phase 56 (note 162) — its audio fix folds into the consumer-migration task below.

### Blocking decisions — Phase 64

- [ ] **Reconnect / eviction / start-race concurrency contract (invariants + red scenarios, no production code)** — both impls below are heavy and touch ≥2 hazard classes (async reopen/send, stateful `_yielded`/`_supersededSeen`/pending-start, lifecycle reconnect/reconcile/yield/takeover); their failures are **silent** (stranded on deploy, duplicate/lost child, new root wiped by a late reset). Write down the invariants and RED scenarios driven by breath+meditation concurrently — SUPERSEDED-only-yield vs bare-close-reconnect, latch gates reopen (app-resume can't re-take), reconcile-by-arrival + root-via-re-open, reset-then-adopt ordering, retry-only-unconfirmed + same-token + adopt-existing + settling-window defer. No production code (m37). The two impls below turn their halves green. Spec: `.ai-factory/notes/24-rootchild-reconnect-concurrency-contract.md`.
- [ ] **Reconnect via `root.id` header + abandoned/reconcile handling** — the header `module-session-id` carries the last child today (`ModuleStateChannel.dart:72-79`); server `handleReconnect` ignores it when memory is alive and, when memory is lost, returns a generic `{abandoned:true}` if the header id is `ABANDONED`. Root death ⟺ whole-tree death (synchronized grace), so send **`root.id`** in the header; treat `{abandoned}` as a global reset (all adapters + bio + snackbar); rebuild the registry by reconcile-by-arrival from the **per-child** RESUMED frames that land. Note: the reconnect fan-out carries **no root frame** (mind_api note 45) — `root.id` is (re)learned from the RootStateChannel ROOT re-open (note 15), not the fan-out; trust the now-truthful `is_paused` on RESUMED frames (mind_api Phase 62). Connection is **single-stream-per-user, last-connect-wins**: yield ONLY on an actual `session_error{code:'CONNECTION_SUPERSEDED'}` before close (track per-stream `_supersededSeen`) → set `_yielded`, go passive, no reconnect (latch gates `_openSessionStream` so even app-resume can't re-take — mandatory ping-pong fix). A **bare** graceful close (deploy/shutdown/revoke, no code) → **reconnect** + reconcile (self-correcting: if that reconnect is evicted, its close carries the code → yield then). `onError` → reconnect (unchanged). Explicit "use here" `takeOverHere()` clears the latch → clean RESUMED root, no children (server ended them). No client connection id (server keys eviction by `(userId, service)`). Spec: `.ai-factory/notes/20-rootchild-reconnect-header-abandoned.md`.
