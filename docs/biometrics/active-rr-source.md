# ActiveRrSource — клиентский единственный активный источник RR

`ActiveRrSource` — синглтон уровня приложения (`App.shared`). Он выбирает один активный источник RR-интервалов из числа зарегистрированных и публикует их через единственный стрим. Это клиентская политика выбора источника — в противовес серверной политике слияния, которую реализует `BioStreamRouter`.

## Две политики потребления RR

Одни и те же RR-интервалы от физического устройства обрабатываются двумя параллельными политиками:

**`BioStreamRouter`** (Phase 21) — серверный конвейер. Регистрирует каждый зарегистрированный источник, сливает все потоки вместе, каждый сэмпл несёт тег источника (`SensorSource`). Агрегация и аналитика происходят на сервере. Ни один сэмпл не теряется: если два устройства дают RR одновременно, оба уходят на сервер с тегами.

**`ActiveRrSource`** — клиентский конвейер. Из тех же зарегистрированных источников выбирает ровно один — «активный» — и публикует его интервалы в единственный стрим. Единственный потребитель сегодня — `HeartRateTickService`, который превращает RR-интервалы в тики дыхательного движка.

Контракт поддерживает любой клиентский UX, которому нужен один выбранный сердечный источник, без знания о политике слияния.

## Предпочтительный источник с откатом

Источники регистрируются в приоритетном порядке при `App.initialize()`; индекс 0 побеждает. Список неизменен после построения.

В каждый момент времени активен источник с наименьшим индексом, который сигнализирует в окне тишины. Если более приоритетный источник оживает в середине сессии (возобновляет эмиссию RR-интервалов), он перехватывает активный слот при следующем своём интервале.

## Формула окна тишины

Источник считается «замолкшим» если с момента последнего интервала прошло больше:

```
max(2000 мс, lastIntervalMs × 2)
```

Два удара тишины на текущем каденсе — порог для объявления источника мёртвым. При срабатывании таймера `ActiveRrSource` обходит список в порядке приоритета и выбирает следующий источник, чей последний интервал укладывается в пол. Если ни один не подходит — `hasActiveSource` переходит в `false` и стрим замолкает. `SwitchableTickService` реагирует на тишину и автоматически откатывается к `ClockTickService`.

## Политика артефактов

`RrInterval.isArtifact == true` логируется и прокидывается дальше как есть (MVP). Единственный `if (rr.isArtifact)` в `_onInterval` — точка вставки будущего фильтра. Анимация поглощает ±10–20 % beat-to-beat вариацию (дыхательная синусовая аритмия) без дополнительного сглаживания.

## Слой сглаживания SmoothedRrSource

Над `ActiveRrSource` стоит синглтон `SmoothedRrSource` (`App.shared`). Он фильтрует артефакты (молча, без повторного логирования) и публикует простое скользящее среднее (SMA) последних 7 принятых интервалов. Именно `SmoothedRrSource` питает `HeartRateTickService`.

`ActiveRrSource` остаётся **сырым** — его окно тишины и политика выбора источника не изменились.
