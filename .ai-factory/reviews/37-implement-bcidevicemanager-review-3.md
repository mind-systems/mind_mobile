## Additional cross-checks

- **Manual `disconnect()` race against provider's broadcast event** — `_suppressAutoReconnect = true` is set before `_provider.disconnect()`, and the provider's controller `add(disconnected)` schedules delivery asynchronously, so by the time the unexpected-disconnect listener fires, both `_state == disconnected` (set immediately after the await returns) and `_suppressAutoReconnect == true` short-circuit reconnect. Two layers of defense, both correct.
- **Cancel-then-`onDone` interaction** — `_attemptReconnect`'s data handler does `await _scanSub?.cancel(); _scanSub = null; await connectDevice(...)` on match. Per Dart stream contract, no events (including `onDone`) are delivered after `cancel()`, so the `onDone` guard `_state == scanning` will never see a transient `connecting` state.
- **`_disposed` discipline** — every write path (`_setState`, both scan handlers) early-returns on `_disposed`. `dispose()` sets the flag first, then cancels subs, then closes controllers. Even if a scan handler is parked on `await connectDevice(...)` when dispose fires, the eventual `_setState(impedance)` no-ops cleanly.
- **`startCalibration` precondition** — `if (_state != BciConnectionState.impedance) return;` is silent (no log). The plan budget says "minimal logging"; an out-of-band call indicates a UI bug, not a runtime hazard. Acceptable.
- **`onDone` and `_connectedSerial` interplay** — `_attemptReconnect` is only invoked from the unexpected-disconnect handler, which itself only fires when `_connectedSerial != null`. The `onDone` callback's `_connectedSerial != null` check is therefore redundant but harmless.
- **Public stream getters forwarding from `_provider`** — `signalQualityStream`, `batteryStream`, and `calibrationStream` return the provider's streams directly. Since `NeiryBciProvider` declares them as broadcast controllers, multiple subscribers (manager's internal `_calibrationSub` + downstream `BciNotifier`) coexist without interference.
- **Auto-connect cache snapshot** — `cachedSerials` is captured once at scan start, not re-read per emission. Matches the spec's "cache already had data when the screen opened" rule.
- **Linter / analyzer** — clean.
