# Экран сопряжения

Экран сопряжения проводит пользователя через три последовательных этапа в одном прокручиваемом полотне: обнаружение устройства, проверка качества контактов, калибровка. Все три секции отрендерены всегда — недоступные пока показаны приглушёнными, чтобы пользователь видел путь целиком.

## Поток этапов

```
discovery ──▶ impedance ──▶ calibrating ──▶ ready
```

- **Discovery.** Список найденных устройств обновляется по мере сканирования. Устройства, с которыми пользователь уже подключался, помечены как «known». Если в эфире нашлось известное — автоматически инициируется подключение, и пользователь сразу видит индикатор «подключаемся».
- **Impedance.** После BLE-коннекта секция оживает: на каждом канале появляется цветной индикатор качества (зелёный — норма, жёлтый — пограничный, красный — нужно поправить электроды). Кнопка калибровки доступна; пользователь решает сам, когда сигнал достаточно чист.
- **Calibrating.** Запущенная калибровка показывает прогресс по этапам и инструкцию «закройте глаза» (или аналог). По завершению проигрывается короткий звук-маркер, и экран переходит в финальное состояние с зелёным «ready». Сбой возвращает в impedance — повторить можно без переподключения.

## Шапка экрана

Индикатор батареи устройства слева, кнопка «Отключить» справа. Батарея и disconnect показаны приглушёнными, пока устройство не подключено. Disconnect защищён диалогом подтверждения — случайный тап не разрывает связь. Выход с экрана — свайп-бэком (iOS) или системной кнопкой назад (Android); явной кнопки закрытия нет.

## Отказ Bluetooth

Когда домен сообщает о постоянном отказе в разрешениях, экран показывает диалог с объяснением, зачем нужен Bluetooth, и кнопкой «Открыть настройки». Открытие настроек — ответственность UI, не домена. После возврата из настроек пользователь сам инициирует повторное сканирование.

## Контракт с доменом

Экран не подписывается на устройство напрямую. Вся коммуникация идёт через сервис-интерфейс на границе модуля: сервис конвертирует доменные события в DTO, ViewModel принимает только DTO. Это позволяет UI-пакету `packages/bci_module/` оставаться полностью отделённым от `lib/Bci/` и от вендорского SDK.

См. [docs/core/module-system.md](../core/module-system.md) — общий паттерн для всех модулей.
